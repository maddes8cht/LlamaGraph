## Strengths

- Key binding tests use `event_generate` and `update()` for realistic simulation
- Camera save tests cover roll presence, roll absence, and exception paths exhaustively
- Surface fallback tests exercise both the normal and exception paths with mocked `_draw_trisurf`
- Right sidebar tests cover the full lifecycle: build section, select/clear, filter change dispatch
- CSV parser tests use `capsys` to verify the warning-print behavior noted in known issues
- Consistent use of test classes with clear section comments

## Weaknesses

- Right sidebar `_build_section` tests require 6 patches per test, making them brittle to widget changes
- `get_3d_points_string_params_returns_empty` merely documents a known bug (asserts `len == 0`) — it's a placeholder, not a behavioral test
- CSV warning tests check exact substring in `captured.out` — fragile if warning format changes
- No integration tests that wire view + presenter end-to-end

## Risks

- Right sidebar mocking is deep: a refactor that changes widget creation order would break many tests
- String-param tests pass trivially (empty lists) — could give false confidence about the known bug being "handled"
- CSV warning tests rely on `print()` statements that may be replaced by logging in the future

## Recommended Follow-ups

- Consider reducing right sidebar test mocking by extracting widget creation into a factory or using integration-level fixtures
- Replace the `get_3d_points` string-param placeholder tests with actual fixes when the model is updated to handle string dimensions
- Consider adding end-to-end tests that wire view + presenter together for key workflows
